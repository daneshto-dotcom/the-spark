## §0 — CF-S153-ctx CLOSED FIRST: the context tracker DOES over-report, and here is the mechanism

The carry-forward asked whether `real-context-tokens.py` over-reports, because S153 made **two real scope cuts** on its readings (61 % and 69 %) while the owner's UI read 52 %. Settled empirically before any other work, because this number gates every scope decision in this session.

| Invocation | cwd | `discovery_source` | Reported | Source transcript |
|---|---|---|---|---|
| `real-context-tokens.py` | `Founder DNA/` (parent) | `cwd_derived_slug` | **42.58 % / 425,793** | a **2026-07-11** transcript, model `claude-opus-4-8`, a *different session* |
| `real-context-tokens.py` | `…/The Spark` | `cwd_derived_slug` | 10.1 % | this session (coincidentally the newest file) |
| `real-context-tokens.py --session-id be6c0fd0-…` | either | `cli_session_id` | **10.62 %** | this session, deterministically |

**Root cause.** The script's discovery ladder ends in heuristics: after `--session-id` and `$CLAUDE_SESSION_ID`, every remaining rung resolves a *project slug* and then takes **`max(*.jsonl, key=mtime)`** in that directory (`newest_in_slug`, line 71-75), with a final `global_mtime_fallback`. `$CLAUDE_SESSION_ID` is **UNSET** in this shell, so a bare invocation never identifies the running session — it identifies *the most recently written transcript near the cwd*. Two demonstrated failure modes:

1. **cwd drift** — one `cd` into the parent project makes it report a six-week-stale number from another model's session, as reproduced above.
2. **A concurrent session in the same project** — whichever transcript was flushed last wins. `69e273e0-…jsonl` in this project's directory was written **08:59 on 2026-08-27**, i.e. concurrently with S153's close, so S153's readings are exactly the case this breaks.

**Fix adopted for this session (no script edit needed):** every reading is taken as
`python ~/.claude/scripts/real-context-tokens.py --session-id be6c0fd0-07e3-4da0-9908-8bbeaa3d60c6`
and a reading is only trusted when the JSON echoes `discovery_source: "cli_session_id"`. Any reading whose `discovery_source` is `cwd_derived_slug` or `global_mtime_fallback` is discarded, not debated.

**Consequence for scope:** S153's two cuts were made on an unvalidated instrument. At a verified **10.6 %** the whole approved batch fits with very large margin, so nothing in this PDR is trimmed for budget.
