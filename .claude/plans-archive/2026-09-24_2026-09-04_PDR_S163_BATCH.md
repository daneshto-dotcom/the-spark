### THREE THINGS A.0 FOUND THAT THE INHERITED LIST DID NOT SAY

**1. The self-crown margin is 0.5–5 s, not the 11–14 s I first computed — and I had it wrong
mid-session.** I initially read the peers' promotion deadline off `HOST_STARVATION_MS` (6 s) and
concluded the peers migrate long before the host's 20 s forfeit. That is false. `main.ts:2697-2712`
promotes at `graceMs + ladderDelayMs`, where `graceMs = RECONNECT_GRACE_MS = 15_000` (`main.ts:1858`)
and `ladderDelayMs = rank · CLAIM_LADDER_MS` (1500, `succession.ts:78`). `HOST_STARVATION_MS` only
gates *detection*, not promotion. So rank-0 promotes at **15 s**, rank-3 at **19.5 s**, against the
host's self-crown at **20 s** (`PEER_DROP_FORFEIT_TICKS`, `constants.ts:2399`). The handoff's "the
margin is thin" was right; my arithmetic was not.

**2. `EndGameMsg` HAS NO EPOCH FENCE — an un-fenced win injection.** `protocol.ts:938-941` is
`{ kind: 'ENDGAME', winnerId }` and nothing else. `sync.ts:127` fences NETSNAPSHOT with
`if ((msg.epoch ?? 0) < this.currentEpoch) return false;`, but ENDGAME has no such gate, while
`clientHandlers.ts:64`'s own threat docblock names *"fake a win via ENDGAME"* as a thing it guards.
The guard is peerId-only. So the deposed host of finding 1 can still end the migrated peers' match.

**3. `isValidRoster` never range-checks or de-duplicates `seat`.** `protocol.ts:1313-1336` checks
`typeof r.seat !== 'number'` and nothing more — `-1`, `99`, `1.5` and `NaN` all pass, and two entries
may carry the SAME seat. Both writers of `hostSeats` (`main.ts:2768`, `hostHandlers.ts:529`) feed
straight off that roster, which is the actual root of the two separate findings filed as Lane2-F5 and
HAND-3. Fixing the boundary closes both at one point.

### P1 — THE HOST SELF-CROWN + THE UN-FENCED ENDGAME (Standard)

**OBJECTIVE.** A host whose own uplink dies must not crown itself while its peers migrate and keep
playing.

**PRECONDITIONS (hand-verified, and narrower than the inherited claim).** Networked, **>=3 seats**,
host alive, **>=1 castle already razed**, every living peer past the 20 s clock. Unreachable at 2
seats: `fallenCount` derives from `living`, not `contenders` (`gameState.ts:141`), so a bare
disconnect can never end a match — `elimination.test.ts:465` already pins that. Bots cannot widen it
(no peer, so the predicate returns false).

**SCOPE.**
1. `hostTick.ts:422` — pass the offline predicate only when `deps.alivePeerIds !== null &&
   deps.alivePeerIds.size > 0`; otherwise call `tickGameState(world, deps.gameStateExtras, P1)` with
   no predicate, which `gameState.ts:135` already documents as byte-identical pre-S162 behaviour.
   Rule: **a forfeit-path win requires at least one witness still connected to the host.**
2. `protocol.ts` — add optional `epoch` to `EndGameMsg`; drop it client-side when
   `(msg.epoch ?? 0) < session.currentEpoch`, mirroring `sync.ts:127`. **Additive-optional, so no
   PROTOCOL_VERSION bump** per this project's own protocol rules; a stale peer keeps today's gate.
3. A 3-seat regression test beside `elimination.test.ts:446` asserting still-PLAYING when every
   living peer is offline. A 1v1 fixture cannot express this bug.

**REJECTED, WITH REASONS.** (a) "refuse when >1 seat excluded" — partial, gives false confidence.
(c) widen the forfeit window — belt-and-braces only, and if ever adopted must be a DERIVED constant
so the coupling is compile-visible. (d) a real uplink-health signal — a new trust surface for
protection (b) already gives; if the owner wants it later, ship it as a diagnostic first.

**NOT IN SCOPE — OWNER QUESTION.** `hostHandlers.ts:357` gates demotion on
`gameState === 'PLAYING'`, so once a host has crowned itself no verified higher-epoch claim can unwind
it. Widening that arm would **make a WIN reversible**, which is a design decision about what the
host's screen then shows. Filed, not silently chosen.
