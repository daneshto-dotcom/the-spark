## ⛔ THE FIRST THING TO KNOW: I REPORTED NUMBERS IN THE WRONG UNIT ALL SESSION

The sim stores combat in **FIFTHS** — `attackFifths(atk,pen) = atk * (5 + pen)` — a fixed-point
trick to keep the arithmetic integral. **150 fifths IS 30 points.**

I quoted the raw fifths to the owner in the P2 PDR, a stats table and four commit messages ("150
damage against a 143 pool"). Every RATIO was correct; every NUMBER was in a unit he does not think
in. He caught it: *"if a locusts cloud has 10 atk and 10 pen then his damage should be 10*3 = 30 not
143??"* **He was right.**

⇒ **`node scripts/stat-table.mjs` prints the whole roster in POINTS.** Use it for every stat
conversation. It was written this session so this cannot recur — and the table it produces then
became the evidence for the biggest open item in the game (R171-R, below).

## ⚠ THREE LESSONS THIS SESSION PAID FOR

1. ⛔ **NEVER BIND A VERIFICATION TO SOMETHING THAT IS SUPPOSED TO CHANGE.** The Stop hook hard-failed
   me **three times**, all the same family: a pinned `PROTOCOL_VERSION = 45` (P2B correctly bumped
   it), a HEADCOUNT of constants (the locust fix correctly added one), and exact function SIGNATURES
   (P6 correctly added a parameter). Bind to what must remain TRUE, never to its current shape.
2. **Run `npm run typecheck` after TEST edits, not only source edits.** Twice, vitest went fully
   green while `tsc -b` inside `npm run build` caught a type error in a test file. vitest strips
   types.
3. **A guard and the thing it guards can share one blind spot.** The atlas checker measured row size
   from the all-opaque bbox — and so did the BUILDER's `normaliseStateScale`, where that number is
   the divisor in a rescale. The speck did not merely mismeasure the row, it shrank it, and the
   checker was blind for the identical reason. Both now use the largest connected component.
